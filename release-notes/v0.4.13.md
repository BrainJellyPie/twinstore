TwinStore v0.4.13 improves automatic setup and shopper simulation with local
models, including the reported missing or invented rack-ID failures.

- **Automatic products:** constrain choices to real rack/category/product IDs,
  recover invalid grouped answers with smaller tasks, and respect catalog size,
  available shelf space and the global category limit.
- **Customer generation:** assign customer IDs and traffic hours in the harness,
  preserve uploaded evidence and instructions through every stage, and constrain
  batch sizes and shared customer labels. Recover oversized or truncated batches
  with bounded splitting while retaining visit times and population totals.
- **Local model reliability:** preserve 8,192 context tokens per managed server
  slot, recognize supported local protocols, respect endpoint credentials and
  model identity, and prevent repeated retries or stale answers after a model
  change. Optional cache-write failures no longer discard valid responses.
- **Long store prompts:** compact repeated catalog/exposure information and
  recover input-context failures with one candidate-selection pass. Requests
  that still exceed the model's capacity fail explicitly.
- **Accurate purchases:** retain exact offers, prices and reachable shelf copies;
  reject unseen or unreachable purchases before applying limits; and preserve
  checkout timing. Impulse decisions receive the actual planned basket and each
  shopper's individual needs. Counterless layouts no longer fail on a generated
  checkout action.
- **Model response handling:** keep useful answers with absent optional text,
  separate final JSON from leading thinking blocks, validate numeric/geometry
  bounds before caching, and constrain vision choices to displayed shelf badges.
  Receipt, package-reading and automatic study drafts receive matching guards.
- **Responsive and durable workflows:** keep model discovery, settings waits and
  large playback reads off the request loop, speed up large-fixture analysis,
  and preserve shopper interview and paired-study identities across platforms.

The release workflow checks the backend and web build, then verifies first start
on Linux x64, Windows and macOS before publication. Linux arm64 is cross-built.
