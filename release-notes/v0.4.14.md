TwinStore v0.4.14 brings the local-model fixes developed since v0.4.13 into the
downloadable app, with stronger recovery and fewer silently misapplied answers.

- **Local model requests:** send native Ollama schemas, preserve input context
  during generation, and retain output-cutoff signals through the SDK. Named
  llama.cpp/vLLM providers disable template thinking for structured tasks.
  Endpoint credentials, request slots, retries and failure advice now remain
  consistent across local addresses, aliases and self-hosted LAN servers.
- **Automatic setup and customer generation:** reduce failing starter tasks
  down to single rack rows when needed; preserve valid optional fields and known
  label spellings without inventing IDs, prices or decisions. Truncated uploaded
  data summaries cannot become customer evidence.
- **Faithful shopping decisions:** keep selected offers, reachable placements,
  personal intent and categories throughout planning, impulse purchases and
  interviews. Missing required decisions enter bounded recovery instead of
  silently becoming empty visits; optional impulse lists may still be empty.
- **Studies and layout drafts:** retain distinct shelf prices and locations,
  require explicit promotion text, and reject ambiguous product or image names.
  Automatic moves can use a reachable existing shelf face. Multi-product A/B
  drafts have enough output space, while blank required staff-script answers
  are excluded from paired comparisons.
- **Shelf and receipt reading:** keep different variants and pack sizes
  separate, validate prices before applying them, retain unreadable receipt
  entries for review, and save package crops under the applied product identity.
- **Rival comparisons:** require confirmed product identity, avoid arbitrary
  reference prices, split oversized requests into smaller batches, reject
  contradictory requested matches, and prioritize relevant store products
  within the existing catalog limit.
- **Local runtime and interface:** recover compatible GPU builds across partial
  releases, install matching CUDA libraries beside the server, detect vanished
  external servers, and preserve complete Unicode characters when copying
  study names.

The release workflow checks the backend and web build, then verifies first start
on Linux x64, Windows and macOS before publication. Linux arm64 is cross-built.
Protocol regressions use scripted HTTP responses; they do not measure a local
model's real-world answer accuracy.
