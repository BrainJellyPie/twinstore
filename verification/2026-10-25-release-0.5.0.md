# v0.5.0 release preparation

The latest public release is v0.4.14. This candidate is the
`claude/online-shopping-features-ji7y0f` branch with current `main` merged in
(including the Ollama Qwen3.5 answer-budget and blank-narrative fixes released
after v0.4.14, and the online-store follow-ups on `main`: stock limits, a single
currency per comparison, retrying truncated model answers, metadata search,
project protection during runs, de-duplicated imports and wishlist paging, each
with its own verification record). It adds online stores and groups the Unreleased entries under
0.5.0, with versioned release notes and a README section.

## Online stores

- 42 templates over the bundled catalog: every template builds, product IDs are
  unique, every product belongs to a category of its site, list prices exceed
  sale prices and each category has best sellers. KRW sites use Korean names
  and 100-won prices.
- Browser state machine: popups block the page until answered, the menu is a
  modal drawer, back returns through history, search modes (smart, exact, off),
  sorting and paging, cart totals (shipping threshold, coupon, last-step fee,
  pre-ticked add-on), guest and forced-account checkout, one-page and
  multi-step checkout, buy-now and sold-out products.
- Screenshots: every option a page offers has a drawn box, checked by a
  randomized crawl over six templates on desktop and mobile (after it found and
  fixed checkout controls that were offered but not drawn). Rendering is
  deterministic per page and badge numbering.
- Shoppers and sessions: panels are reproducible; eyesight is drawn from its own
  random stream so changing it keeps every other attribute. Rule sessions are
  reproducible and end properly; model sessions send the screenshot (vision) or
  page outline (text), fall back to rules on failed calls, and ask one exit
  survey per visit. Rule-shopper rates were calibrated by mission against
  plausible ranges (window shoppers about 9 % conversion, purchase intent about
  55 %); they remain illustrative priors, not fitted behavior.
- Analysis: funnels are monotone, segments include eyesight, friction rows count
  popup, sign-in, fee and add-on events, survey summaries compute NPS, and paired
  survey differences use only shoppers who answered in both stores.
- API: template previews, site lifecycle and variants, validation errors,
  browsing (including the search box and eyesight preview), rule and fake-vision
  runs, session replays with the chosen option highlighted, clickstream CSV, run
  deletion and recovery of interrupted runs after a restart.

## Checks

- Backend: Pyright strict on all sources, zero errors. The full suite on the
  candidate with `main`'s online-store follow-ups merged (b61308bf), run in a
  clean worktree: 41,274 passed, 1 skipped (25 minutes). Before that merge the
  same suite gave 41,045 passed, 1 skipped. An earlier run had reported 12
  failures in unrelated starter-selection, evidence-retry and vision-badge
  tests because the branch was moved to newer `main` test fixtures while it
  ran; those tests pass on clean `main` and on this candidate.
- Frontend: `tsc`, `pnpm lint` (no errors; the existing route-file
  fast-refresh warnings remain) and the full Vitest suite, including i18n
  completeness and placeholder checks for every new key in six languages.
- Browser: the built app was driven with Playwright in English and Korean:
  template gallery, creating a store, browsing by clicking the screenshot,
  searching, the low-vision preview, saving a variant, a two-store rule run, the
  report with friction audit and segments, and a replay. No console errors.

Publishing (pushing `release/v0.5.0`, which runs the release workflow, creates
the tag and uploads the archives) is a separate step and is not claimed here.
