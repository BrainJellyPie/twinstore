# Complete interface localization — ongoing coverage log

The target is every end-user workflow in English, Korean, Chinese, Japanese, Spanish and French,
not just navigation. Each batch includes descriptions, labels, accessibility names, validation,
progress, empty/error states, review and save/retry. User-authored names, SKUs, model identifiers,
API values and stored data are not translated. Raw technical diagnostics remain available unchanged
under a translated disclosure, with localized actionable guidance above them. Model-generated
language and server-returned domain explanations require separate coverage; do not count them as done.

## Batch 1: uploaded photos → reviewed layout

The entire LibraryPhotos dialog uses the existing locale store: entry/title/description, explanatory
copy, replacement toggle, search, selection counters, all menu options, empty/loading states, image
alternative text, preview, saving/retry/open and limits. Complete sentences interpolate values without
translating user content. Validation stores message keys until render so switching language updates
an already-visible error. No locale is added to the API request or query identity.

The shared DialogFooter had an English-only Close button even though DialogContent's dismissal was
localized. Both now follow the selected language. Shared RequestError supplies translated HTTP-status
guidance and a translated technical-details disclosure; the diagnostic text itself is preserved.

Validation evidence is recorded after actual runs; local logs are under
`/workspace/.verification/twinstore-i18n/`. Basic existing photo/i18n suites: 51 passed. The separate
boundary phase adds all-six-language save/open tests, language changes during pending preview and
uncertain saves, selection/filter/request-ID preservation, literal user names and error retranslation.
An initial test clicked before a QueryClient notification was rendered and saw a stale-preview alert;
the test now waits for the empty-library state before exercising the missing-photo validation. This
was a test synchronization error, not a product defect.

Browser review also caught awkward singular/plural text such as French `1 produits`. Count summaries
now use labels (`Produits : 1`) instead of appending a fixed plural noun. Related suites passed again
after this copy fix. The shared footer's untranslated dismissal is covered in all six languages.

## Batch 2: bulk product editing

Integrated main 19919b7d, ai-ux-loop 7a49d436 and store-scenarios 6b9ec692 in c920350b,
d96e08de and b378688b. Preserved all histories and both changelog additions; the operator-only
localization entry remains unreleased rather than being attributed to the already-published 0.4.5.

The product bulk editor translates all instructions, accessible input labels, mixed-value placeholders,
counts, validation, undo/reset/reload, preview and save/retry/open states. Price presentation follows
the chosen locale; editable prices retain the existing exact decimal-point convention with a translated
hint. Language changes cannot reinterpret an existing numeric draft. Stored names, promotions, SKU,
currency and numeric values are not translated. The table is keyboard-focusable and horizontally
scrollable; its accessible name explains this behavior.

Basic checks: 55 passed. Separate localization boundary tests: 64 passed, including all six languages,
exact rounding, maximum safe-integer prices, Unicode/user markup, selection and undo preservation,
visible validation retranslation, and language changes during pending/uncertain saves.

Two boundary defects were reproduced and fixed:

1. Product workflow HTTP clients discarded the status when converting errors to generic `Error`.
   RequestError therefore displayed generic guidance even for conflicts or invalid input. A real
   client → localized UI regression failed all 12 status/client cases before the fix. Library photos,
   product editing, shelf copies and starter fill now throw the existing `ApiError` with status and
   original diagnostic intact. The tests passed afterward; mocked component errors alone had not
   revealed this transport gap in batch 1.
2. French Reset/Reload buttons extended beyond a 390 px viewport despite wrapping text. The browser
   measured dialog client width 354 px versus scroll width 436 px and failed before the fix. Bound
   button width to the available space. Give the product table its own scroll region and readable
   column width; the dialog itself no longer scrolls horizontally. Also removed duplicated currency
   codes from localized preview amounts. Final six-language browser checks passed both viewports.

After repairs, the affected product/i18n suite passed **154 tests in 8 files** (24.45 s). The real API
browser script `product-editor-i18n-browser.mjs` verifies selection → bulk price → preview → save →
open in every language, at 390×844 and 1280×640, and that 1.005 USD becomes exactly 101 cents for both
placements while every other field and the source remain unchanged. No page errors. The French mobile
screenshots in French, Chinese and Japanese were visually checked. Browser logs/screenshots are in the `browser-1` artifact subdirectory.
