# v0.4.12 release preparation

The 207 branch heads returned by the GitHub API on 2026-10-24 were all ancestors
of main `0e94e7f709218cae9d6cee134a8c6194ea58e2a9`. No additional branch merge was
needed. That main contains 331 commits after v0.4.11, including merge commits.

The release preparation groups the existing Unreleased changelog under 0.4.12 and
adds a shorter versioned release note. It does not change application behavior.

The available GitHub connector can update repository refs but cannot dispatch a
workflow or create a release directly. The existing release workflow therefore
also accepts `release/v*` branch pushes. It resolves and validates the version once
and passes it to both the launcher build and publication. Tag/manual triggers keep
their existing behavior, including snapshot builds with no version. Publication
still binds the tag to the exact build commit and refuses an occupied version.

Nine local workflow tests passed in 0.596 seconds. They include branch, tag,
manual and snapshot version resolution; malformed version rejection; versioned
release notes plus download instructions; and existing tag-race protections.
The application fixes have their focused checks recorded in the other verification
documents. The existing CI workflow performs its release checks and platform smoke
runs before publishing. This document records preparation, not CI completion.
