# v0.4.13 release preparation

All six remote branch heads were checked against main
`eb3373f57afe7e838c998a6de5f8749700db3489`. Every head is included; no merge is
required. That main contains 86 commits since v0.4.12.

This preparation groups the existing Unreleased changelog under 0.4.13 and adds
versioned release notes. A remaining HTTP test adapter identified traffic by the
old concrete schema name; the new opening-slot schema is a subtype. Its twelve
budget-repair cases failed at that test-only dispatcher before reaching customer
generation. The adapter now recognizes the traffic field, preserving the budget
assertions and avoiding a concrete subtype-name dependency.

Application changes already have focused verification documents. Preparation
passed 20 affected budget checks in 2.63 seconds and nine release-workflow tests
in 0.648 seconds; `git diff --check` is clean. The existing
release pipeline runs its backend/frontend and packaged-platform checks before
publication. This document records preparation, not CI completion.

The release uses the existing `release/v0.4.13` branch trigger because the GitHub
connector can create branches but cannot dispatch workflows or publish releases
directly. The workflow binds the tag and four archives to the same source commit.

The first CI run, 40118904736, passed the web build and 2,228 backend tests before
an older readiness fixture failed. Two fake managers declared `ready` without
the server address that the endpoint-specific readiness guard now requires.
The fixture supplies that address; production readiness checks remain intact.
The affected file reproduced two failures in isolation. After correction, 150
assistive selection, endpoint-readiness and fallback checks passed in 3.58
seconds. The release branch is advanced to this tested correction before retrying
publication; no release tag or assets were published by the failed run.

The second CI run, 40119256161, reached 11,154 passing tests before an initial
assortment fake mistook the constrained category-schema subtype for a product
request. Three exact-class checks in the format and project-template test
adapters now accept that subtype. The original geometry, currency, category and
product assertions are retained. All 751 affected assortment/template/selection
checks passed in 17.02 seconds; this correction changes no application code.

The third CI run, 40119970939, passed 27,785 tests before detecting lost
price-specific advice in the conjoint API. Moving semantic validation inside
the model correction loop had wrapped application-owned price errors in a
generic validation failure. The API still rejected the invalid drafts, but its
message no longer explained the price problem. Four isolated cases reproduced
the regression. Price guards now emit a typed Pydantic error; only that error
from the terminal attempt supplies its application-owned message to the API.
Raw model inputs are not exposed, and an earlier price error does not mask a
later provider timeout. All 93 focused API, error-advice, currency-boundary,
model-recovery and study-level checks passed in 4.52 seconds. Strict backend
type checking passed with zero errors; `git diff --check` is clean.
